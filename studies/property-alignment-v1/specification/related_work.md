# Related work and novelty boundary

| Source | Inspected material | Established contribution | Consequence for this work |
|---|---|---|---|
| [D24](https://arxiv.org/abs/2406.11795v1) | Open manuscript formulation and runtime-assurance sections, particularly section 3.2 | Spacecraft inspection combines learned control with an explicit runtime-assurance filter and multiple constraints. | A new spacecraft filtering method must be compared with a capable constraint-aware baseline; our old one-step screen is insufficient as the sole comparator. |
| [B26](https://doi.org/10.2514/6.2026-3088) | Retained Crossref title, authors, proceedings type and DOI; current public author/institution event record | Published proceedings identity and its targeted-testing subject are verified. | No first-ever discovery of runtime-assurance failures is claimed. No comparison may infer absent capabilities from unavailable text. |
| [BR22](https://arxiv.org/abs/2212.08900v1) | Sections III-V; observer/error bounds, equations 12-18, assumptions and Theorem 1; official certification code | Observer error bounds, predictive tubes and terminal/backup constructions already support constrained output-feedback safety. | Combining uncertainty, state estimation and predictive backup is established prior art; use a faithful robust baseline. |
| [W21](https://arxiv.org/abs/1812.05506) | PDF pages 4-6; Definition 3.1, Section 4, Assumption 4.2 and backup algorithms | A safe terminal set and previously feasible backup plan support recursive protection beyond a nominal one-step test. | One-step acceptance cannot replace a justified backup/terminal obligation; that principle is established. |
| [S20](https://arxiv.org/abs/2005.06418v1) | Sections III-C and IV; Theorems 1-2, Corollary 1 and input-history algorithm | Stored inputs, sampled-data reasoning and state-error enclosures can account for delayed command application. | Delay-history propagation and robust intersample constraints are not new contributions. |
| [MP19](https://arxiv.org/abs/1811.06502v2) | Sections 3-5; fallback definition, Theorems 1-3 and sensor-uncertainty monitoring conditions | Verified monitor implications already address uncertainty, actuator disturbance and recovery conditions. | Proving a generic monitor-to-safety implication or noting uncertain sensing is not novel. |
| [L20](https://arxiv.org/abs/2005.07144v2) | Section II and II-A, PDF pages 4-5; reachable/avoid sets and execution assumptions | Safety under loss of observations and finite blackout durations already has a differential-game/reachability formulation. | A blackout budget must offer a specific computational or evidential advance beyond existing safety kernels. |
| [OR15](https://eecs481.org/readings/testoracles.pdf) | Section 2 definitions and introduction, PDF pages 1-4 | Oracle information, formal specifications and partial predicates already organize evaluation claims. | An executable schema or independent predicate is supporting verification practice, not a new general assurance theory. |
| [NASA11](https://ntrs.nasa.gov/citations/20110011506) | Title/author record and PDF page 17, abort and navigation account | The mission used a preplanned separation corridor and a separately located safe-hold destination during an abort. | Abort geometry is mission-specific; the benchmark union cannot be asserted as an operational requirement. |
