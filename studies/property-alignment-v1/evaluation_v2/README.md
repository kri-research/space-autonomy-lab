# Replacement common-command evaluation

This additive module prepares Task 08D. It does not replace the original frozen
files or the invalid first attempt. The primary question, four parameter proposal
distributions, equal weights, 768 selected inputs, 13 qualification commands,
one-second candidate policy budget and original analysis implementation are retained.

## Explicit amendment

Qualification now uses `qualification_repair_v1.core.qualify`, the validated
immutable-queue check and exact queue-state reuse. True eligibility requires every
hypothesis to have a continuously checked fixed-library prefix. False eligibility
distinguishes a checked precommand violation from failure of a sufficient library
search. None is an execution/assumption blocker and cannot be excluded as an
ineligible input. Definite qualification claims are rechecked with the unmodified
full-schedule implementation or the checked attainable queue witness. A failed
recheck blocks selection. Global equivalence of the old and repaired conservative
certification domains is not asserted.

All reserve qualification completes before any full-set candidate call. Exactly
192 eligible inputs per stratum are chosen in fixed index order. Unknown
qualification or an exhausted reserve prevents that selection. Candidate,
comparison and in-episode proof recheck are the unchanged `evaluation.episode`
implementation. Any selected timeout, crash or interrupted start contributes zero
primary successes and is retained without retry. Unstarted work alone may resume.

## Fresh protected inputs

The replacement generator changes only seed-namespace salts. Before scientific
execution it retires exact information sets already present in the old reserve,
known development/calibration inputs or candidate fixtures, and duplicates in the
new reserve. Every such identity-only retirement is recorded. This explicit
finite-population exclusion preserves the parameter proposal distributions, not
an unsupported claim of independent identically distributed operational data.
The same conditional-mean concentration analysis remains applicable. No outcome,
initial-membership, qualification, trajectory or candidate calculation is used to
choose the replacement reserve. Original study records are never pooled into it.

## Execution and evidence

Four spawned workers, a 15-second whole-case watchdog and 30-minute phase limits
remain fixed. Each worker records its case identity and phase; unknown computation
is distinct from a negative geometric certificate. Atomic write-once receipts,
content digests, batch/run locks and the private one-identity registry prevent
silent reruns and accidental overwrites. Hashes are integrity checks rather than
an independent assurance theorem or proof of absent prior access.

Only eight already exposed original calibration inputs are used for full-path
integration in this task. Real-clock serial/parallel runs retain every result;
deadline-sensitive outcomes may differ between machines or repetitions. Checkpoint,
crash and timeout tests are explicitly synthetic. No physical validation or
independent human review is claimed.

## Reproduction

Use the existing isolated baseline environment and pinned historical evidence.
From the study root, `python -m pytest evaluation_v2/tests` exercises calibration
and synthetic fixtures only. `python -m evaluation_v2.verify --freeze
evaluation_v2/frozen/freeze.json` checks identity without scientific execution.
The optional `--runtime` flag also checks the bound local environment.

The exact protected execution command is stored in the new freeze and must be
invoked only for Task 08D. No old command is re-enabled. Any scientific/source
change after this deposit needs a new prospective amendment and preserved old
identity. A successful frozen evaluation would support the bounded diagnostic
claim, not general recovery, controller superiority or flight readiness.
